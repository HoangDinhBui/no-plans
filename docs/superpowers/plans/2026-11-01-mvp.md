# NO PLANS MVP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Track evidence in codex.md.

**Goal:** Implement the approved private-group planning MVP across Go API, PostgreSQL, Expo mobile and web invitations.

**Architecture:** Go modular monolith and separate worker, PostgreSQL transactions and outbox. Supabase supplies identity; every business mutation passes through Go.

**Tech Stack:** Go, PostgreSQL, React Native/Expo, TypeScript, Supabase Auth, Expo Push.

**Spec:** docs/system-design.md (approved by user on 2026-11-01).

## Global Constraints

- Private groups/plans; no public stranger discovery, payments or chat.
- Owner counts toward capacity; RSVP is atomic and idempotent.
- UTC storage, Asia/Ho_Chi_Minh display default.
- No authentication bypass in production; never commit secrets.
- Update codex.md after verified milestones; physical push/device testing is required before beta.

## Review Focus

- Concurrent last-seat RSVPs must not oversubscribe.
- Cross-user identifiers must never grant access.
- Expired/revoked links and duplicate redemptions must preserve limits.
- Stale plan versions and reminders must not overwrite/send obsolete changes.
- Lost network responses and retried mutations must not duplicate effects.
